ASCII Fireworks Animated: The Night Sky Programme

Two small firework programs share this repo. One prints rows of asterisks in a terminal. The other draws filled circles in a pygame window and puts a stick figure next to each burst. This page is the printed programme for that night: the sky first, then the two acts in order, then how to run them yourself.

I wrote both scripts in 2023. I have left what they do, and what they do not do, exactly as the code says it.

The sky above is a page version of the same idea, drawn here in the browser: rockets rise and burst into falling characters. It is not program output. The real shows are the two scripts below, one in a terminal and one in a pygame window. The figure on the ground line is stick_figure.png, the repo file the large script loads. In that script the figure appears up and to the left of each burst. On this page I stood it on the ground to watch, which is where a person at a fireworks night actually stands.

Before the showWhat this is

I wrote the minimal script to find out how little code a firework needs. The answer was one loop. Pick one of four ANSI colors, red, green, yellow, or magenta. Print a row of 5 to 15 asterisks. Sleep for a tenth of a second. Do it again, forever, until Ctrl+C. There is no grid, no position tracking, and no burst shape in that file. The terminal scrolling does the rest of the work.

The large script is the same idea taken into a window. It is not ASCII, and my README says so plainly. It fills a 700 by 500 pygame window black, draws one filled circle with a darker ring around it, places the stick figure beside it, and then does the whole thing again. Nothing stays on screen between frames, so the show is a strobe of single bursts rather than a sky that fills up.

Order matters in this programme because the size jump is the story. Act One is 48 lines and needs nothing but Python 3. Act Two is 89 lines, needs pygame, and needs stick_figure.png sitting next to it. Everything after the acts is notes, plates, and the run commands.

Act One: minimal-fireworks.py

The terminal act. Each call to firework() prints one row: a color code, then a run of asterisks. I left blue and cyan out on purpose, because on the dark terminal I ran this on, red, green, yellow, and magenta read clearly. I picked 5 to 15 stars because shorter rows vanished in the scroll and longer rows looked like a solid bar.

EndingCtrl+C is caught. The script prints the reset code once, then returns.

Excerpt from minimal-fireworks.py, lines 31 to 44, at the head this page was built from.

31def main():
32    try:
33        while True:
34            firework()
35            # This sleep is the frame rate. Without it the loop prints as
36            # fast as Python can, the terminal scrolls past too quickly to
37            # read as fireworks, and one core stays pinned.
38            time.sleep(0.1)
39    except KeyboardInterrupt:
40        # I catch Ctrl+C here instead of letting the traceback out. Leave
41        # the terminal the way it was found: without the reset code the
42        # last firework's color stays active in the user's prompt.
43        print(RESET)
44        return
II.

Act Two: large-fireworks.py

The window act. Each frame picks a center at least 50 pixels from the edge, a color from a list of seven, and a radius from 10 to 50. The trail is not a streak. It is a ring drawn first, in the same color with each channel halved, and the bright filled circle is drawn over it, so what you see is a dark band around a bright disc.

Run it yourselfHow to run them

# Act One: Python 3 only. Stop it with Ctrl+C.
python3 minimal-fireworks.py

# Act Two: install pygame first, then run it from any folder.
pip install pygame
python3 large-fireworks.py

Honest notesWhat the code does not hide

  • These are 2023 scripts and they read like 2023 scripts. Small, direct, and not built to handle cases they never met.
  • The minimal script never clears the screen and never looks at the terminal size. A narrow terminal and a wide one get the same 5 to 15 asterisks per row. The scroll is the whole stage.
  • The large script does not clear a terminal either. It fills its own window black each frame. If stick_figure.png is missing, it stops at load time with an error that names the file. I left that in, because the scene has nothing to show without the figure.
  • The large script waits 100 milliseconds with no clock object, and that wait also sets how often it checks for a close click. The window can take a beat to notice. That is in the code comments because it cost me time to understand.
  • Near the top or left edge, the figure offset can push part of the figure off the window. Pygame clips it and the next frame moves on. I did not fix that, and this page does not pretend I did.
  • The GitHub description for this repo still says fireforks. I know. I left the description as it stands in the record, and this page spells the word right.
